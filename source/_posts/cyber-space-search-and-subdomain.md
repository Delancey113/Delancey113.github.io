## 一、实验目的

1. 了解网络空间搜索引擎的工作原理，及相似功能搜索引擎
2. 掌握 ZoomEye 的基本搜索语法，能按组件、端口、域名三个维度检索资产
3. 能用至少三种方法完成目标域名的子域名收集

## 二、实验环境

- 操作系统：Windows 10
- 数据来源：ZoomEye Web 
- 目标域名：`guet.edu.cn`


## 三、与 ZoomEye 功能类似的搜索引擎

|------|------|------|--------|

## 四、ZoomEye 实战

### 4.1 常用搜索语法

| 字段 | 含义 | 示例 |
|------|------|------|
| `app:` | 组件 / 产品名 | `app:"Apache"` |
| `os:` | 操作系统 | `os:Linux` |
| `title:` | 网页标题 | `title:"后台管理"` |
| `port:` / `service:` | 端口 / 服务 | `port:8080`、`service:ssh` |
| `country:` / `city:` | 国家 / 城市 | `country:CN` |
| `ip:` | IP 或网段 | `ip:202.193.64.0/24` |
| `hostname:` / `site:` | 域名 | `hostname:guet.edu.cn` |

### 4.2 搜索一：按组件检索

- 语法：`app = "nginx" && country = "CN"`
- 历史累计命中：102,931,532 条
- 近一年数据：30,607,659 条
- 查询耗时：3.510 秒

ZoomEye 同时给出了「历史累计」与「最近一年」两个数字，二者相差约 3.4 倍。
这说明测绘引擎本质上是一个持续更新的**快照库**，而非实时监视器：库中约三分之
二的记录在近一年内未被再次观测到，可能已下线、变更 IP 或完成升级修复。因此
在做资产梳理时，应以「最近一年」的数据衡量当前暴露面，直接使用累计总量会显
著高估实际情况。

从单条结果看，目标返回 `302 Moved Temporarily` 并携带 `Location` 跳转至
HTTPS 地址，同时设置了 `Strict-Transport-Security`，说明其已强制启用 HTTPS
并配置了 HSTS。其 `Server` 字段仅返回 `nginx` 而未暴露具体版本号，推测已关闭
`server_tokens`，这在一定程度上提高了攻击者定位已知漏洞的门槛。

另外，命中的主机名中包含 `test` 字样，属于典型的测试环境遗留资产。此类系统
通常缺少正式的补丁维护与访问控制，在实际攻防中是优先关注的对象。

![按组件检索结果](/img/zoomeye-nginx.png)

### 4.3 搜索二：按端口 / 服务检索

- 语法：`port = "6379" && country = "CN"`
- 历史累计命中：1,637,018 条
- 近一年数据：478,657 条
- 查询耗时：0.178 秒

6379 是 Redis 的默认端口。国内近一年约有 47.8 万台主机的 Redis 端口处于
公网可达状态。累计数据与近一年数据同样相差约 3.4 倍，与上文 nginx 的检索结果
呈现出一致的比例关系，进一步印证了测绘引擎「快照库」的特性。

从单条结果看，该主机 Banner 返回 `-NOAUTH Authentication required`，表明连接
已建立但要求身份认证，即该实例已启用密码保护。作为对比，若 Banner 直接返回
`+PONG` 或版本信息，则说明实例未设置认证，任何人皆可读写其中的数据，即典型的
Redis 未授权访问情形。

![Redis 端口暴露情况](/img/zoomeye-redis.png)

### 4.4 搜索三：针对目标域名检索

- 语法：`domain = "guet.edu.cn"`
- 历史累计命中：214 条
- 近一年数据：213 条
- 查询耗时：0.865 秒

与前述通用检索相比，本组数据的数量级差异显著：全网口径下的 Redis 暴露主机达
47.8 万台，而一个组织对外暴露的 Web 资产仅两百余条。

此外，本例累计数据与近一年数据几乎一致（214 对 213），与前述 nginx、Redis 两组
相差 3.4 倍的情况截然不同。原因在于，大范围通用检索中包含大量已下线、变更地址
的陈旧记录，而组织内部系统一旦上线便长期在线，变动很小
从响应头看，目标返回 `200 OK` 但 `Server` 字段为空，即服务器未返回该字段。
结合前两组结果，可归纳出信息隐藏的三个层级：

| 配置状态 | 典型响应 | 说明 |
|----------|----------|------|
| 默认 | `Server: nginx/1.18.0` | 软件与版本全部暴露 |
| 隐藏版本 | `Server: nginx` | 版本已隐藏，软件类型仍可识别 |
| 完全隐藏 | 无 `Server` 字段 | 需借助其他指纹推断 |

## 五、三次检索结果汇总


| 检索目标 | 检索语法 | 历史累计 | 近一年 | 累计/近一年 |
|----------|----------|----------|--------|-------------|
| nginx 组件（国内） | `app = "nginx" && country = "CN"` | 102,931,532 | 30,607,659 | 约 3.4 倍 |
| 6379 端口（国内） | `port = "6379" && country = "CN"` | 1,637,018 | 478,657 | 约 3.4 倍 |
| 目标域名 | `domain = "guet.edu.cn"` | 214 | 213 | 约 1 倍 |

**结论一：通用检索的两个口径差异稳定在 3.4 倍左右。**

nginx 与 Redis 两组的比值几乎完全一致。大范围的通用检索覆盖全网，
其中包含大量已下线、更换地址、完成升级的陈旧记录，因此历史累计必然显著高于近期
观测值。

**结论二：单一组织的资产口径稳定，两个数字接近。**

目标域名一组的累计与近一年仅差 1 条。组织内部系统一旦上线往往长期在线，变动很小，
因此两个口径几乎重合。即**当两个数字接近时，说明数据稳定、结论可信；
相差悬殊时，则需警惕陈旧记录对分析结论的干扰。**


## 六、子域名收集


### 6.1 方法一：搜索引擎语法检索

在普通搜索引擎与测绘平台中用语法检索，直接筛出属于该域名的页面。

```text
site:guet.edu.cn                       百度
site:guet.edu.cn -site:www.guet.edu.cn 排除主站，只看其他子域名
domain = "guet.edu.cn"                 ZoomEye（见 5.4，214 条结果）
```

这一方法的局限是：只有被搜索引擎收录或被测绘引擎扫到的子域名才会出现，收录不全。

### 6.2 方法二：证书透明度日志（CT Log）

**原理：** HTTPS 证书的签发记录是公开的，任何机构为域名申请证书都必须写入
证书透明度日志（Certificate Transparency Log），而证书里会列明它覆盖哪些子域名。
因此只要翻这份公开日志，就能反推出某个域名历史上申请过证书的所有子域名。

操作：浏览器打开 https://crt.sh ，在搜索框输入 `%25.guet.edu.cn` 回车。
`%.` 是 SQL 通配符，表示"该域名下的任意子域名"。

![crt.sh 查询结果](/img/subdomain-crtsh.png)

本次查询共命中 **41** 条证书记录，去重后得到 **14** 个不同域名。

从结果里能读出三点信息：

1. **`*.guet.edu.cn` 是通配符证书**，表示这一张证书覆盖该域下所有子域名。
   这类记录无法告诉我们具体有哪些子域名，只能证明存在通配符部署。
2. **具体的子域名**出现在个别记录里，例如 `mba`、`idp`、`lockapi`、`cas`、
   `tdcwx`、`dcwx`、`guetpan.obs.cn-south-235`。
3. **签发机构有多个**：DigiCert、RapidSSL、Let's Encrypt、GlobalSign、TrustAsia。

### 6.3 方法三：DNS 数据聚合

- `https://api.hackertarget.com/hostsearch/?q=guet.edu.cn`（直接返回「域名,IP」纯文本）
- https://dnsdumpster.com
- https://searchdns.netcraft.com
- https://rapiddns.io/subdomain/guet.edu.cn

![DNS 聚合站点查询结果](/img/subdomain-dns.png)

本次查询返回 **44** 条「子域名,IP」记录。右侧统计显示，其中 **41 条都指向同一个
IP `202.193.64.75`**，另有 3 个 IP 各承载 1 条。

### 6.4 结果汇总与交叉验证

把两种方法的结果合并去重，共得到子域名 **55** 个。

| 方法 | 命中子域名 | 与对方重合 | 独有 |
|------|-----------|-----------|------|
| 证书透明度日志（crt.sh） | 14 | 3 | 11 |
| DNS 数据聚合（hackertarget） | 44 | 3 | 41 |
| **合并去重后** | **55** | — | — |


**关键发现：41 个子域名共用同一个 IP。**

`202.193.64.75` 这一个 IP 承载了 41 个子域名。这说明域名前方存在**统一的入口
设备**（反向代理 / CDN / WAF），真实业务服务器的 IP 被隐藏在后方。
